# 06. Часы (Apple Watch Ultra 2)

## 1. Режимы исполнения

| Режим (`execution`) | Фаза | Кто исполняет | Плюсы | Минусы |
|---|---|---|---|---|
| `workoutkit` | 1 | Штатное приложение «Тренировка» (запланировано через `WorkoutScheduler`) | Ноль своего кода на часах, максимальная надёжность и полнота записи, офлайн | Алерт пульса срабатывает только при переходе границы, сигналы не настраиваются |
| `zone2_watch` | 2 | Наше приложение на часах (`HKWorkoutSession`) | Постоянный сторож пульса, свои сигналы, свой UI | Свой код записи тренировки; нужно добиться паритета со штатным приложением |
| `zone2_trainer` | 1.5 | Наше iOS-приложение у станка (FTMS) + наше приложение на часах (пульс, запись) — [11-trainer](11-trainer.md) | План сразу на экране, одна запись в Health с мощностью и пульсом, без MyWhoosh и HeartCast | Свой код; ERG — отдельным этапом |
| `mywhoosh` | 1 (запасной) | MyWhoosh на Mac + станок; пульс с часов транслирует HeartCast | ERG по `.zwo` (только при мощностных таргетах) | Загрузка `.zwo` руками (AirDrop → конструктор); Mac-клиент теряет кастомные тренировки после перезапуска; часы заняты HeartCast — WorkoutKit не ставим |
| `none` | — | Без структуры (силовая на телефоне, «по самочувствию») | | |

AI выбирает режим в `plan_workouts`. По умолчанию для бега, вело на улице и бассейна — `workoutkit`; для станка — `mywhoosh`, после этапа A2 станка — `zone2_trainer`; после фазы 2 — `zone2_watch` для тренировок со сторожем.

## 2. Фаза 1: WorkoutKit

- `CustomWorkout(activity:, location:, displayName:, warmup:, blocks:, cooldown:)`; шаги — `IntervalStep(.work/.recovery, goal:, alert:)`.
- Goals: `.time`, `.distance`, `.open`. Open-шаг нашей структуры → `.open` (переход по кнопке).
- Alerts: `HeartRateRangeAlert`, `SpeedRangeAlert`/`PaceRangeAlert` (зависит от версии SDK), `PowerRangeAlert`, `CadenceRangeAlert`. Нужен один алерт на шаг: берётся главный `target`.
- Бассейн: `swimming` + `poolSwimming` с длиной бассейна. **Поддержка custom-тренировок для плавания проверяется в спайке S1.**
- **Пресеты** для свободных тренировок («Easy run HR 125–145»): custom-тренировка из одного открытого шага с алертом. AI держит их запланированными, или приложение предлагает «добавить в Тренировку» через превью WorkoutKit.

## 3. Фаза 2: своё приложение на часах (Zone2 Watch)

**Первая функция — компаньон станка (ф.1.5, [11-trainer §4](11-trainer.md#4-пульс-и-запись-компаньон-на-часах)):** запуск с iPhone, `HKWorkoutSession` indoor cycling, пульс на iPhone через зеркалирование, мощность и каденс с iPhone — в builder часов. Таргет, подпись, `WorkoutLink` и зеркалирование, сделанные для станка, раннер переиспользует.

### 3.1 Состав
- **Today** — тренировка дня и ближайшие 2–3 (из `WatchConnectivity.updateApplicationContext`, хранятся локально на часах).
- **Раннер** — исполнение структурной тренировки или пресета.
- **Настройки сторожа** — профиль сигналов (синхронизируется с `profile.hrGuard`; правит AI или телефон).

### 3.2 Раннер
- `HKWorkoutSession` + `HKLiveWorkoutBuilder` (`HKLiveWorkoutDataSource`) — те же метрики, что у штатного приложения на этом устройстве: пульс, дистанция, скорость, мощность бега, GCT/VO/длина шага, калории.
- GPS: `CLLocationManager` + `HKWorkoutRouteBuilder`.
- Шаги: движок `StepEngine` (чистая логика, тестируется отдельно) — переход по времени, дистанции или Lap (для open-шагов). Lap — тап по экрану; Action Button Ultra (проверить доступность для сторонних тренировок, спайк S6).
- События: `HKWorkoutEvent(.segment)` на каждый шаг с метаданными `stepId` — сервер точно сопоставляет интервалы с планом.
- Метаданные тренировки: `zone2.plannedWorkoutId`, `zone2.version`.
- Зеркалирование на iPhone (`startMirroringToCompanionDevice`) — живой экран на телефоне и основа трансляции пульса (ф.3).
- Пауза и автопауза, восстановление после падения (`recoverActiveWorkoutSession`).

### 3.3 Сторож пульса (HR Guard) — замена Pulsalarm

Требования из опыта с Pulsalarm:

| Боль Pulsalarm | Решение |
|---|---|
| Отдельное приложение | Сторож встроен в раннер и в пресеты |
| Сессия живёт час, потом её надо обновлять | Сторож работает внутри нашей `HKWorkoutSession` — без лимита (лимит около часа — у фоновых сессий приложений, работающих рядом с чужой тренировкой) |
| Сигналы не настраиваются | Профиль сигналов (ниже) |
| Пульс правится руками каждый раз | Коридор берётся из шага плана (`guard` / `target`) или из пресета |
| Застрявшая очередь, старые сигналы при новом старте | Без уведомлений и очередей: прямой вызов `WKInterfaceDevice.play`; машина состояний сбрасывается при старте и смене шага; покрыто тестами |

**Машина состояний** (пакет `HRGuard`, чистый Swift, без зависимостей от watchOS):
```
INACTIVE ──start/step change──► GRACE (graceSec после смены шага, HR догоняет)
GRACE ──timeout──► IN_RANGE | HIGH | LOW
IN_RANGE ──hr > high + hyst за confirmSec──► HIGH  (сигнал «выше» сразу)
IN_RANGE ──hr < low − hyst за confirmSec──► LOW    (сигнал «ниже» сразу)
HIGH/LOW ──каждые repeatSec, пока вне коридора──► повтор сигнала (с эскалацией, если включена)
HIGH/LOW ──hr вернулся в [low+hyst, high−hyst]──► IN_RANGE (сигнал «в зоне», если включён)
нет данных HR > staleSec ──► NO_SIGNAL (отдельный сигнал, один раз)
```

**Профиль сигналов** (`profile.hrGuard`, переопределяется на уровне шага):
```jsonc
{
  "repeatSec": 8,              // как часто повторять, пока вне коридора
  "confirmSec": 4,             // сколько секунд вне коридора до первого сигнала
  "hysteresisBpm": 2,
  "graceSec": 45,              // после старта и смены шага
  "staleSec": 15,
  "high": { "haptic": "directionUp", "count": 2 },
  "low":  { "haptic": "directionDown", "count": 1 },
  "backInRange": { "haptic": "success", "enabled": true },
  "escalate": { "afterSec": 60, "haptic": "failure" },  // если долго вне коридора
  "sound": false,              // звук поверх музыки — выключен по умолчанию
  "lowEnabled": true, "highEnabled": true
}
```
Тесты: синтетические последовательности пульса → ожидаемая последовательность сигналов (golden), включая «рваный» пульс, пропуски данных, быструю смену шагов, двухчасовую сессию.

### 3.4 Паритет со штатным приложением (критерии приёмки ф.2)
Одна и та же пробежка записана параллельно в двух режимах (тест на улице): дистанция ±1%, ряды пульса и трек сопоставимы, механика бега присутствует, тренировка корректно появляется в Health, Fitness и Strava (через наш хаб, ф.3).

## 4. ~~Фаза 3: трансляция пульса в MyWhoosh (замена HeartCast)~~

**Отменено (D49):** станок ведёт наше приложение ([11-trainer](11-trainer.md)), пульс идёт с часов на iPhone через зеркальную сессию, HeartCast и MyWhoosh не нужны. Ниже — исходная идея для истории.

Сейчас это делает HeartCast, и FIT MyWhoosh уже содержит пульс — основной путь данных станка от этой фичи не зависит ([05-sync §7](05-sync.md#7-mywhoosh--сервер--health)). Своя трансляция нужна, чтобы убрать отдельное приложение и лишнюю запись в Health:
часы (`HKWorkoutSession` indoor cycling, зеркалирование) → iPhone (`CBPeripheralManager`, стандартный Heart Rate Service `0x180D` / характеристика `0x2A37`) → MyWhoosh на MacBook видит iPhone как пульсометр. Запись тренировки на часах при этом не сохраняется в Health (или помечается как источник пульса для склейки) — чтобы не плодить дубль.

## 5. Ограничения бесплатной подписи для часов
Приложение для часов подписывается той же Personal Team. Подпись живёт 7 дней: ставится вместе с iOS-приложением скриптом еженедельной переподписи. Лимиты Personal Team на число App ID учитываются в `project.yml` (минимум таргетов и расширений в фазе 1).
