# 01. Требования

> Название проекта — **zone2.day** (по домену). Модули в коде — `Zone2*`.
> Статус документа: v1.1 — утверждено, дополнено по ревью «глазами тренера» (2026-11-14).

## 1. Видение

Личное приложение для тренировок на выносливость (бег → триатлон: бег, вело, плавание, силовые), где **тренер — AI**.
Атлет обсуждает план в чате с AI (claude.ai), AI через MCP пишет план в облачную базу. План сам, без ручных действий, оказывается на телефоне и на часах — даже если на улице нет интернета. Выполненная тренировка автоматически попадает в Apple Health и в базу, где AI видит её с максимальной детализацией (вплоть до сырого FIT).

Референс: blocks.zone (чужой продукт, похожая идея). UI не копируем, делаем лучше.

## 2. Действующие лица

| Актор | Как взаимодействует |
|---|---|
| **Атлет** | Чат с AI; iOS-приложение (просмотр + лог весов в зале); Apple Watch Ultra 2 (исполнение тренировки) |
| **AI-тренер** | Удалённый MCP-сервер. Основной клиент — claude.ai (web/desktop/mobile), также Claude Code |
| **AI-разработчик** | Агент, который разрабатывает и отлаживает систему: тесты, симулятор, логи, debug-инструменты MCP |

## 3. Функциональные требования

### 3.1 AI-доступ (MCP) — FR-MCP
- **FR-MCP-1.** AI полностью управляет данными: читает и пишет профиль, план, старты, блокнот; читает тренировки, метрики здоровья, силовые логи.
- **FR-MCP-2.** Выполненные тренировки доступны с максимальной детализацией: сводка → круги/интервалы → временные ряды (1 Гц) → **сырые файлы** (оригинальный дамп HealthKit, FIT — оригинальный или сгенерированный).
- **FR-MCP-3.** Все производные числа (зоны, нагрузка, попадание в план, интервалы) считает сервер; ответы содержат подсказки интерпретации (`howToRead`, `basis`, `confidence`).
- **FR-MCP-4.** Каждое изменение плана несёт `why`, попадает в журнал изменений и может быть откачено (`revert_change`).
- **FR-MCP-5.** AI видит статус доставки: дошла ли конкретная версия тренировки до телефона и до часов.
- **FR-MCP-6.** **Блокнот AI**: страницы markdown, которые AI ведёт сам (долгосрочная память между чатами); синхронизируются в приложение как офлайн-база знаний.
- **FR-MCP-8.** Ручной ввод через MCP: активность со слов атлета, импорт FIT/GPX, силовая задним числом (перенос из Notion); слова атлета, sRPE и официальный результат на активности.
- **FR-MCP-9.** Аналитика фазы 1: GAP, Pw:HR и декаплинг по ровным участкам, тренд эффективности (темп/мощность при пульсе), нагрузка = объём по видам спорта + sRPE × минуты.
- **FR-MCP-7.** Подключение к claude.ai как custom connector (OAuth 2.1). Для Claude Code — тот же OAuth или персональный токен.

### 3.2 План — FR-PLAN
- **FR-PLAN-1.** Календарь тренировок: дата, порядок внутри дня (`order`, без времени), вид спорта, название, цель (зачем), заметка, ключевая/нет, контекст-теги, ссылки на блокнот, явный пропуск с причиной.
- **FR-PLAN-1a.** Недели: заголовок, шапка (вектор, что заморожено, правила) и итог недели — пишет AI.
- **FR-PLAN-2.** Структура тренировки: шаги и повторы; длительность по времени / дистанции / **открытая** (open goal: без заданной длины, до нажатия Lap); таргеты по темпу, пульсу, мощности, RPE, каденсу; абсолютные или % от порога. В день может быть несколько тренировок.
- **FR-PLAN-3.** Силовая: упражнения, подходы × повторы × вес, RPE, суперсеты, заметки. Время подходов и отдыха не планируется и не логируется (кроме удержаний в статике).
- **FR-PLAN-4.** Старты: вид, дистанция, приоритет A/B/C, цель, заметки. Статус от **идеи** («интересно, решения нет») до принятого и зарегистрированного. Дата может быть **неточной** («начало июня 2027»).
- **FR-PLAN-5.** Плавание: бассейн (длина — параметр тренировки), стиль, инвентарь. Открытая вода — позже.
- **FR-PLAN-6.** Тренировки на станке исполняются своим приложением (FR-TRAINER). Запасной путь: экспорт в `.zwo` для MyWhoosh (только при мощностных таргетах).
- **FR-PLAN-7.** Журнал атлета: дни без активности, симптомы, снаряжение и посадка, открытые вопросы со сроком.
- **FR-PLAN-8.** Снаряжение (обувь с пробегом), трассы (GPX, участки, сравнение визитов — ф.2).
- **FR-PLAN-9.** Часовые пояса: дом + поездки; дата плана, «сегодня» и время на часах — в поясе места, где атлет находится в этот день.

### 3.3 iOS-приложение — FR-IOS
- **FR-IOS-1.** **Офлайн-first.** Всё отображаемое читается из локальной базы. План появляется без кнопки «обновить».
- **FR-IOS-2.** Экраны: Today (с шапкой недели), Calendar (недели, журнал в днях), детали тренировки (план; после выполнения — план и факт рядом), детали активности, старт (офлайн-план гонки, ф.2), профиль (с блокнотом), debug.
- **FR-IOS-3.** **Режим зала**: лог фактических подходов и весов (префилл из плана, подтверждение тапом, правка), заметка к упражнению. Работает офлайн, синхронизируется позже.
- **FR-IOS-4.** Автоматическая отправка тренировок из Apple Health на сервер, включая полный дамп рядов; бэкфилл **всей истории**; удаление в Health удаляет/скрывает активность.
- **FR-IOS-5.** Синхронизация метрик восстановления: HRV, пульс покоя, сон, вес, VO2max.
- **FR-IOS-6.** Планирование тренировок на часы через WorkoutKit (штатное приложение «Тренировка»).
- **FR-IOS-7.** Запись в Apple Health активностей, пришедших извне (MyWhoosh), если их там ещё нет.
- **FR-IOS-8.** Поделиться `.zwo` (AirDrop на Mac → конструктор MyWhoosh) — запасной путь для станка.
- **FR-IOS-9.** Интерфейс на английском, с локализацией (ru — второй язык) с первого дня.
- **FR-IOS-10.** Остальной ввод данных в приложении не требуется: обратная связь — через чат.

### 3.4 Часы — FR-WATCH
- **FR-WATCH-1 (фаза 1).** Структурные тренировки исполняются штатным приложением «Тренировка» (WorkoutKit), пишутся в Apple Health.
- **FR-WATCH-2 (фаза 2).** Своё приложение-раннер на часах с **постоянным сторожем пульса** (замена Pulsalarm): сигнал повторяется, пока пульс вне коридора; коридор берётся из шага плана; сигналы настраиваются; нет «часового» лимита сессии; нет застрявших очередей.
- ~~**FR-WATCH-3.** Трансляция пульса с часов в MyWhoosh~~ — заменено FR-TRAINER-2: HeartCast не нужен, пульс снимает наше приложение на часах (D49).
- План силовых на часах **не нужен**.

### 3.4a Станок — FR-TRAINER ([11-trainer](11-trainer.md))
- **FR-TRAINER-1.** iPhone подключается к станку (ThinkRider X2Max, BLE FTMS) без сторонних приложений: живые мощность, каденс, скорость; тренировка из плана идёт по шагам с целями и таймером; экран не гаснет. Без 3D-мира и игровых функций.
- **FR-TRAINER-2.** Пульс — с Apple Watch через наше приложение на часах (первая функция Zone2 Watch, замена HeartCast); заезд записывается в Apple Health одной тренировкой с пульсом, мощностью и каденсом и уходит на сервер обычным путём.
- **FR-TRAINER-3.** Без часов заезд всё равно записывается (с телефона, без пульса).
- **FR-TRAINER-4 (позже).** ERG: станок сам держит мощность шага.

### 3.5 Источники данных — FR-SRC
- **FR-SRC-1.** Apple Health — основной источник (часы).
- **FR-SRC-2.** ~~MyWhoosh (станок X2MAX) → intervals.icu → наш сервер забирает оригинальный FIT~~ — заморожено (D48): заезды на станке пишет своё приложение (FR-TRAINER). Ручной импорт FIT остаётся.
- **FR-SRC-3 (позже).** Наш сервер — хаб: выгружает активности в Strava (вместо MyWhoosh → Strava и Health → Strava).

### 3.6 Аккаунты — FR-AUTH
- **FR-AUTH-1.** Многопользовательская модель данных с первого дня (изоляция по `user_id`).
- **FR-AUTH-2.** Фаза 1: вход по **passkey** на `zone2.day`. Регистрация — по инвайт-коду.
- **FR-AUTH-3.** Позже (с платным Apple Developer): Sign in with Apple как привязанная идентичность.

## 4. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-OFFLINE | Без сети приложение показывает весь план и историю; тренировки уже на часах; лог зала пишется локально |
| NFR-DELIVERY | Изменение плана доходит до телефона без действий пользователя: в фазе 1 — при любой фоновой активации или открытии; в фазе 3 — через push за секунды |
| NFR-COST | $0 в месяц на одного пользователя (кроме домена) |
| NFR-PORTABLE | Переезд бэкенда (Supabase → VPS) — замена адаптеров и конфигурации, без переписывания доменной логики; публичные URL не меняются |
| NFR-PRIVACY | Медданные: изоляция пользователей, токены хранятся хэшами, файлы — по подписанным ссылкам с коротким TTL, ничего не отдаётся третьим сторонам, кроме явно подключённых интеграций |
| NFR-AI-DEV | Каждая часть проверяется агентом автоматически: тесты, снапшоты UI, MCP-контракты, удалённые логи устройства |
| NFR-I18N | UI: en + ru; данные в SI-единицах; тексты AI — на языке атлета |
| NFR-UI | Нативный, чёткий, приятный UI; Dynamic Type; тёмная тема; читаемость на улице |

## 7. Ключевые сценарии (acceptance)

1. **«План уже в часах».** Вечером в claude.ai: «поставь на завтра 10 км с 6×10 с в горку». AI → `plan_workouts`. Без открытия приложения тренировка при ближайшем фоновом пробуждении попадает в локальную базу телефона и в «Тренировку» на часах. На вопрос «дошло?» AI отвечает по `get_delivery_status`. Утром интернета нет — всё на месте.
2. **«Разбор пробежки».** После пробежки тренировка из Health автоматически уходит на сервер (как только есть сеть). В чате AI вызывает `get_context` → `get_activity` → видит план рядом с кругами и сам оценивает выполнение, дрейф пульса, при необходимости ряды и FIT.
3. **«Зал».** На телефоне открыта силовая; подходы предзаполнены; отмечаю фактические веса тапами без сети. Позже AI видит план-vs-факт и прогрессию по упражнению.
4. **«Станок».** AI ставит тренировку на станке (`execution: zone2_trainer`). Включаю станок, открываю тренировку на iPhone → «Start on trainer»; часы сами открывают наше приложение и снимают пульс. Еду по шагам, глядя на экран телефона. После «Стоп» заезд с пульсом, мощностью и каденсом — в Health и через обычный экспорт на сервере; AI разбирает его как любую тренировку. (До готовности — MyWhoosh + `.zwo` + ручной импорт FIT.)
5. **«Лёгкий бег под сторожем» (фаза 2).** Запускаю «Z2 125–145» в нашем приложении на часах. Пока пульс выше 145 — вибрация повторяется каждые N секунд, пока не вернусь в коридор. Час, два, три — без перезапусков.
