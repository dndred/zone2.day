# Спайк S4 — частота фоновых пробуждений без push

Старт: 2026-11-14 16:08 UTC (23:08 Барнаул). Устройство: iPhone 16 Pro, iOS 27.0.1. Сборка: debug, Personal Team.
Код: `ios/App/Spike/S4WakeMonitor.swift`, вкладка «S4». Журнал: `Documents/wakes.jsonl` (`just ios-pull Documents/wakes.jsonl`).

## Что пишется
Одна JSON-строка на пробуждение: `trigger` (`launch`, `foreground`, `bg.refresh`, `hk.workout`, `hk.steps`), состояние приложения, доступность сети (`GET /health` staging, мс).
Триггеры: `BGAppRefreshTask` (перепланируется на +30 мин при каждом запуске и уходе в фон), `HKObserverQuery` + background delivery (тренировки `.immediate`, шаги `.hourly`).

## Условия замера
- Обычная жизнь 3–5 дней; приложение **не смахивать** из переключателя (смахнутое приложение iOS не будит).
- Сигналы HK, совпадающие по времени с `launch`, — первичные срабатывания при регистрации, в статистику не идут.

## Критерий (из 09-roadmap)
Медианный интервал между фоновыми пробуждениями днём ≤ 1–2 ч.

## Находки по ходу
- `BGTaskScheduler.submit` до регистрации обработчика (в `App.init`) роняет приложение (`NSInternalInconsistencyException`). SwiftUI регистрирует `.backgroundTask` после `init` → планировать при `scenePhase == .active/.background` и в самом обработчике.

## Результат
Журнал снят 2026-11-20: копия `day.zone2.app` (на ней шёл замер), 14.11 23:08 → 20.11 10:22 по Барнаулу. 781 событие склеено в 159 пробуждений (события в пределах 90 с считаются одним): 103 пробуждения от пользователя, 56 фоновых (`bg.refresh` есть в 39 из них, в остальных только HK). В копии stg HealthKit не авторизован (`Authorization not determined`), поэтому для замера она не подходит.

| Метрика (день — 09–23 по Барнаулу) | Значение |
|---|---|
| Медиана интервала между фоновыми пробуждениями днём | **0,53 ч** (p75 0,95 · p90 2,2 · max 3,4) |
| Медиана времени от любого запуска до ближайшего фонового пробуждения | 0,64 ч (p90 1,4) |
| Возраст данных днём (время с последнего запуска любого типа) | медиана 0,54 ч · p90 3,8 ч · больше 2 ч — 22 % времени |

**По дням это очень неровно.** 15, 19 и 20.11 приложение просыпалось каждые 30–45 минут, и данные ни разу не устаревали больше чем на 2 ч. 16–18.11 фоновых пробуждений было 2–5 за день, а без единого запуска набирались окна по 4–10 ч (16.11 — с 13:37 до 00:02). Причина не установлена. Возможно, iOS урезала фоновый бюджет после частых переустановок из Xcode в эти дни, или сказался режим использования телефона.

**Ночью** фоновых пробуждений нет совсем: с ~00:30 до ~08:40 приложение не запускается ни разу.

**Сеть:** в 99 из 781 событий `GET /health` не прошёл (`offline`), медианная задержка 0,9 с.

**Вывод:** формально критерий выполнен: медиана 0,5 ч при пороге 1–2 ч. Но гарантии нет: бывают дни с дырами в полдня. Для синка без push этого хватает, а для доставки плана на часы «к утру» — нет. Изменения, которые тренер вносит ночью, приедут только после ~08:40 или когда пользователь откроет приложение. Платный аккаунт и push пока не срочны. Перед доставкой важных изменений стоит полагаться на открытие приложения, а при доставке показывать на сервере свежесть устройства (`get_delivery_status`).
