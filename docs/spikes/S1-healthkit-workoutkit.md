## Выводы и изменения в дизайне

1. **Время для `schedule(_:at:)` не нужно** — передаём только дату. `order` остаётся единственным полем порядка (05 §5).
   Для поездок в `DateComponents` явно ставим `timeZone` = эффективный пояс даты, иначе дата привяжется к текущему поясу устройства.
2. **Strava пишет заезды MyWhoosh в Health.** В списке есть вело-тренировка с `source = Strava`, `HKIndoorWorkout`, `HKExternalUUID`, 17 км / 60 мин — это заезд со станка, который Strava продублировала в Health.
   Следствия для пути станка (05 §7, D27):
   - активность из intervals.icu (оригинальный FIT) и HK-запись от Strava — один заезд → дедупликация по пересечению времени, приоритет у FIT;
   - пока Strava пишет в Health, наше приложение **не пишет** второй экземпляр (`health_export: skipped_overlap`);
   - когда наш хаб начнёт выгружать в Strava (ф.3), запись Strava → Health лучше отключить в настройках Strava, и тогда в Health пишем мы.
3. **Погода в имперских единицах** (°F) — конвертируем при ingest; влажность — `HKUnit.percent()` (0…1 → %), не доверять строковому выводу.
4. **Силовые на часах пишутся** (`functionalStrengthTraining`, 43 мин, без дистанции) → сессия в зале может связываться с `hk_workout_uuid` для времени и пульса.
5. **Длина бассейна в `CustomWorkout` не задаётся** — часы спрашивают/помнят её сами; `poolLengthM` из структуры остаётся информационным (на часы не уходит).
